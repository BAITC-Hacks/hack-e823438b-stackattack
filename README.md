# EventDNA

Каталог event-подрядчиков Казахстана с детерминированным подбором и объяснениями.

## Локальный запуск

Python 3.9+:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

Интерфейс: http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs.
Frontend подключён к API: варианты полей берутся из каталога, поиск показывает до трёх карточек, воронку, WHY THIS и WHY NOT.
Есть состояния загрузки, ошибок и пустого результата. Открывайте сайт через сервер, а не как файл index.html.
WHAT IF пока доступен через `/docs`, отдельного интерфейса для него ещё нет.

## Данные

Замените `backend/data/contractors.csv` исходным CSV в UTF-8 с разделителем-запятой и перезапустите сервер.
В CSV добавлены 66 профилей из предоставленной таблицы: 17 категорий, города Алматы, Астана и значение «Зарубежье».
Исходные значения, включая busy_dates, флаги происхождения и пустые поля, сохранены.
У 9 профилей max_hours не указан: при заданной длительности они исключаются как duration_unknown.
Пустой каталог отражается в `/health` как `dataset_empty`; поиск и WHAT IF возвращают HTTP 503.
Некорректный CSV останавливает запуск с диагностикой. Тестовые профили используются только в тестах.

Списки разделяются `|`, даты имеют формат YYYY-MM-DD, флаги — true/false или 1/0.
Пропуски чисел и флагов сохраняются как неизвестные значения, а не нули.

## Алгоритм

Порядок фильтров: категория → город → формат → занятые даты → бюджет → длительность → язык.
Текст сравнивается без учёта регистра и повторяющихся пробелов. Неизвестная цена исключает профиль;
неизвестная длительность исключает его только при заданной длительности запроса.
Дата в busy_dates всегда исключает профиль. Отсутствие даты в списке не является подтверждением бронирования.
Цена в CSV — стартовая, а не окончательная смета мероприятия.

Ranking: `(budget - price_from_kzt) / budget`, при нулевом бюджете score = 0.
Это индекс запаса бюджета, не оценка качества и не вероятность успеха. Равенство разрешается по ID.
Флаги происхождения данных не влияют на ranking. Возвращается от нуля до трёх подходящих профилей.
Воронка считает оставшихся после каждого фильтра. WHY NOT сохраняет первый отказ каждого
исключённого профиля и отдельно кандидатов ниже TOP-3.
WHAT IF повторно запускает тот же engine: бюджет +50000/+100000/+200000 ₸, дата +1/+2/+3 дня, длительность −1/−2 часа (если результат >0).
Сравниваются все подходящие кандидаты, а не только TOP-3; возвращаются появившиеся и исчезнувшие ID.

## API

- `GET /health` — состояние каталога.
- `GET /api/filters` — значения полей из CSV.
- `POST /api/recommend` — рекомендации, причины и воронка.
- `POST /api/what-if` — сравнение соседних сценариев.

Сохранены алиасы `/filters`, `/recommendations`, `/what-if`.
Пример тела запроса:

```json
{"city":"Алматы","date":"2026-11-14","event_format":"свадьба","category":"Фотограф","budget":400000,"duration_hours":8,"language":"русский"}
```
